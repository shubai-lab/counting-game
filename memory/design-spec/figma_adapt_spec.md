手游在设计的过程中，由于屏幕比例与尺寸的差异，同一内容在不同手机下显示的位置会出现不同，如果不合理适配会出现黑边、 信息错位、 怪异空位、画面拉伸等情况， 一定程度会影响部分玩家的游戏体验。再加上游戏需要一屏显示的整体性与艺术性，因此和普通APP相比，有着更为复杂的规则

在开发过程中需要设定的统一的适配规则进行从上至下的约束，严谨确保每个界面在不同的分辨率下的适配没问题， 以提升设计的界面在不同设备上有更好的体验以及视觉感受。

根据设备设置不同的设计分辨率缩放系数；手机不放大设计分辨率，直接根据长宽比计算空间适配，再缩放显示到屏幕上。

十周年， 场景和ui适配原则为【高适配】，始终以高度变化的比例对控件或背景的宽高进行等比缩放：

【十周年】根据项目用户使用平台确定分辨率的选择为：
       标准移动端=1334px * 750px      （16:9）
       移动端长屏尺寸=1750px*750px     （21:9）
       pc端= 1600px * 900px 
适配安全区
        1. 适配最小比例：16:9。设定固定最大安全区比例为：21:9。
        2. 超过21:9的机型，以21:9为最显示范围 ，居中适配两边留白，资源处理方式如下：
          ·背景资源单独以全屏铺满的资源出图。
          · 贴边规则ue定，距离尺寸距离根据ui出图的标注位置
从适配的角度来说，750（2x）、720（2x）、375（1x）这三个进行比例缩放 做尺寸校准 相对更合适些。

将游戏中的UI控件都赋予一定的锚点适配规则，则在不同分辨率的情况下，界面会自动完成适配；
锚点适配的核心，是界定控件相对屏幕边缘9个基准点的距离或者比例。
元素根据所处界面的相对位置，选取八向对应锚点作为参考，使得控件的画布锚点和屏幕锚点的相对位置不变，但随着屏幕尺寸变化而变化。
1.自动检测刘海屏，(宽-刘海屏宽度*2)/高 > 16:9 = 两边预留出刘海屏的宽度
2.用来判断是不是刘海屏的方法代码参考：
BOOL is_bangs_phone = ((int)((UIScreen.mainScreen.bounds.size.height / UIScreen.mainScreen.bounds.size.width) * 100) == 216)

背景原画输出最大尺寸， 需根据每年用户使用手机分辨率基数 随时跟进更新，

定义：此类型背景一般是缩放、裁切不影响表现的图片。与ui层大小比例没有强关联的。作为在控件背后的虚空、当做背景的远景。

适配规则： 背景图的u3d适配为，全屏居中适配

出图规范：

大于 21:9（1750*750）的屏幕尺寸     基于短边适应屏幕，锚点居中，等比例放大背景，适当裁切；

小于2:1 的屏幕尺寸     基于短边适应屏幕，锚点居中，裁掉背景图片左右部分；

定义：此类背景需要考虑【背景】与【界面信息层】之间的关联在不同适配下，位置是否对应上。可以分两种类型情况进行处理。

与背景关联：与背景一起切图，  适配走背景规则， 居中适配

纯装饰层： 对于界面层无关联信息的图，类原画图或全屏视频。需要制作最大分辨率大小的图片来进行向下兼容，才能在4个分辨率比例下完美适配内容，且需要把主要内容集中在16:9比例下

与ui信息关联：单独切资源， 并与关联ui绑定位置， 做统一适配。都需保持在16:9的比例内，以比例尺寸对于左右两边的距离进行适配

十周年背景 以  21:9  （1750*750）出背景图资源

    （如果觉得背景太过单调，可以增加一个可进行九宫拉伸的装饰型衬线层）
