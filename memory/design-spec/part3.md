# 适配规范

> 从Figma文档"十周年--交互设计规范"页面"---适配规范"提取
> 作者：王立哲
> 提取时间：2026-04-14

## 一、通用适配类型

### 1.1 适配基础原则

**适配原因：**
- 手游在设计过程中，由于屏幕比例与尺寸的差异，同一内容在不同手机下显示位置会出现不同
- 如果不合理适配会出现黑边、信息错位、怪异空位、画面拉伸等情况
- 游戏需要一屏显示的整体性与艺术性，因此有着更为复杂的适配规则

**适配目的：**
- 提升界面在不同设备上的体验和视觉感受
- 确保每个界面在不同分辨率下正确适配

**适配原理：**
- 高度适配：始终以高度变化的比例对控件或背景的宽高进行等比缩放
- 锚点适配：将UI控件赋予一定的锚点适配规则，不同分辨率下界面自动完成适配
- 锚点核心：界定控件相对屏幕边缘9个基准点的距离或比例

**适配安全区：**
- 适配最小比例：**16:9**
- 最大安全区比例：**21:9**
- 超过21:9的机型，以21:9为最大显示范围，居中适配两边留白

**分辨率选择：**
| 平台 | 分辨率 | 比例 |
|------|--------|------|
| 标准移动端 | 1334px × 750px | 16:9 |
| 移动端长屏 | 1750px × 750px | 21:9 |
| PC端 | 1600px × 900px | 16:9 |

**适配范围定义：**
- 内容UI区域：适配最小比例16:9，最大安全边距为2.3:1
- 超过2.3:1的界面以2.3:1安全区为准
- 所标注参考尺寸均以1334×750分辨率为基准，开发时需根据分辨率进行等比放大

### 1.2 适配类型分类

#### 类型一：贴边适配

**适用场景：**
- 固定尺寸UI
- 导航按钮、货币栏等固定元素

**适配规则：**
- 与屏幕边缘固定距离显示
- 贴边规则由UE确定，距离尺寸根据UI出图标注位置
- 贴边类按钮根据条件隐藏/开启时，需做自动对齐适配

**典型应用：**
- 返回按钮+标题：贴左+上屏幕边，固定距离适配
- 货币栏：贴右+上屏幕边，固定距离适配
- 页面主按钮：贴右+下屏幕边，固定距离适配
- 页面次按钮：贴左+下屏幕边，固定距离适配

#### 类型二：内容区域-整体型居中适配

**适用场景：**
- 闭合型模块界面
- 内容可完全在一区域内展示

**适配规则：**
- 内容整体基于显示区域，锚点居中显示
- 当界面内容自成闭合性模块时，与画面是否延展无关，使用中心锚点
- UI和背景有对应关系时，推荐UI和背景都使用居中适配

**十周年游戏内适配：**
- 通用功能性界面，内容整体基于除页签外显示区域，锚点居中显示
- 外围系统固定高度适配，进行宽高等比缩放
- 横向上居中，特殊边缘按钮进行贴边适配

#### 类型三：内容区域-间隔型居中适配

**适用场景：**
- 格目类、列表类界面
- 横向滑动列表

**适配规则：**
- 格目类：单道具格子宽度=w1，列表总宽度=W，道具单行数量=n，道具横向间距=d固定值
- 默认W = w1×n + (n-1)d + M，M∈[0, w1+d固定值]
- 若M能放下一个w1，则自动填充多显示一个条目
- 若M不能放下一个w1，则列表局间距D自适应=w1/(n-1)，左右两边固定贴边适配
- D自适应需根据美观度给一个最大间距值，达到最大间距值时，右边固定间距进行补充间距适配

**注意事项：**
- 列表类的底图UI资源，需支持9宫格拉伸
- 超出一屏的列表，须控制"半个显示"提示滑动方向
- 无法满足半个显示的，需给"浮层UI"箭头提示滑动方向

#### 类型四：非闭合内容区域-列表适配

**定义：**
- 内容在横向上需要滑动，内容不能在一区域内展示完全
- 以格子列表类界面为主

**适配规则：**
- 在可适配的界面范围内，根据界面延展或选项数量自适应距离
- 列表底图需要跟随界面延展做显示的拉伸
- 底图（非大背景）通常需要做九宫设计以便做不同分辨率下的自适应

#### 类型五：闭合内容区域-列表适配

**定义：**
- 内容在横向上无需滑动，内容可完全在一区域内展示完全
- 此类闭合仅特指三国杀十周年

#### 类型六：弹窗适配

**适用场景：**
- 局内外全部弹窗

**适配规则：**
- 弹窗适配以中心锚点为准
- 局外弹窗非全屏类的弹窗，均采用固定尺寸
- 弹窗均固定屏幕中心点显示
- 弹窗层内容位置基于弹窗适配，可锁定屏幕位置进行约束处理

**弹窗安全范围：**
- 安全边距：左右两侧各20px
- 底部安全距离：42px（基于1334×750标准）

### 1.3 页签适配规则

#### 侧页签（一二级）
- 贴左屏幕边，固定距离适配
- 刘海边距按106空出
- 一级页签按照150以内出图

#### 横页签
- 贴左侧页签边，固定36距离适配
- 贴顶部货币栏，固定20距离适配

#### 特殊页签
- 贴右侧屏幕边，固定距离适配
- 贴顶部控件A，固定距离适配

**注意：**
- 目前横向二级tab不支持滑动，且最多显示六个
- 后续如有特殊情况需要具体分析

### 1.4 特殊机型适配

#### 刘海屏适配
- 自动检测刘海屏
- 判断公式：(宽-刘海屏宽度×2)/高 > 16:9 = 两边预留出刘海屏宽度
- 代码参考：`BOOL is_bangs_phone = ((int)((UIScreen.mainScreen.bounds.size.height / UIScreen.mainScreen.bounds.size.width) * 100) == 216)`

#### iPhone灵动岛适配
- 判定设备为iPhone，特殊处理为【侧边缩进】
- 程序在两侧留白106（实际尺寸等比缩放至750高时）
- 控件在"安全区"内显示和适配

#### Home Indicator适配
- 在出图过程中，需保证基于1334×750界面标准下
- 下方操作区域距离界面底端42px
- 其余尺寸给予该尺寸等比例调整实际px
- 控件在"安全区"显示和适配

#### Pad适配
- 屏幕宽高比小于16:9，判定为Pad
- 界面上下方做挡板处理
- 1334×750比例，高750等比适配放大

## 二、十周年适配规范V2.0

> 更新时间：2024.11.18
> 作者：王立哲

### 2.1 适配标注方法

#### 锚点系统
- 将游戏中UI控件赋予一定的锚点适配规则
- 锚点核心：界定控件相对屏幕边缘9个基准点的距离或比例
- 元素根据界面相对位置，选取八向对应锚点作为参考
- 控件的画布锚点和屏幕锚点相对位置不变，随屏幕尺寸变化而变化

#### 9个基准点
- 左上、中上、右上
- 左中、中心、右中
- 左下、中下、右下

**注意：** 9个基准点有时可以多锚点同时并存，具体看界面需求

### 2.2 适配层级结构

为了方便设计适配方案，界面资源分为4个层级：
1. **背景层**
2. **装饰层**
3. **界面信息层（UI层）**
4. **弹窗层**

不同层适配规则独立设定，做到可互相关联，也可互不干扰。

### 2.3 背景层适配

**定义：**
- 缩放、裁切不影响表现的图片
- 与UI层大小比例没有强关联
- 作为控件背后的虚空、远景

**适配规则：**
- 背景图的U3D适配为全屏居中适配

**出图规范：**

| 屏幕尺寸 | 适配方式 |
|----------|----------|
| 大于21:9 (1750×750) | 基于短边适应屏幕，锚点居中，等比例放大背景，适当裁切 |
| 小于2:1 | 基于短边适应屏幕，锚点居中，裁掉背景图片左右部分 |

**注意事项：**
- 背景原画输出最大尺寸，需根据每年用户使用手机分辨率基数随时跟进更新
- 十周年背景以21:9 (1750×750)出背景图资源
- 如界面背景不需要体现界面情绪，尽量制作左右对称且简单的背景图
- 如觉得背景太过单调，可增加一个可进行九宫拉伸的装饰型衬线层
- 如前景有角色或特殊UI，需背景承托，将其作为装饰层，单独裁切，单独适配

### 2.4 装饰层适配

**定义：**
- 需要考虑【背景】与【界面信息层】之间的关联
- 在不同适配下位置是否对应

**分类处理：**

| 类型 | 处理方式 | 适配规则 |
|------|----------|----------|
| 与背景关联 | 与背景一起切图 | 居中适配 |
| 纯装饰层 | 单独切最大分辨率资源 | 需制作最大分辨率图片向下兼容，主要内容集中在16:9比例内 |
| 与UI信息关联 | 单独切资源并与关联UI绑定 | 统一适配，保持16:9比例内，以比例尺寸对左右两边距离适配 |

**特殊处理：**
- 含有侧页签的页面，出背景原画图时，需考虑表现内容被左侧【一级页签、二级页签】遮盖部分的处理方式
- 该层为背景层与界面UI层的特殊分层
- 若部分背景与界面信息有关联，需单独切图，标记资源适配

### 2.5 界面信息层适配

**定义：**
- 界面层同为交互层
- 需要做到细分模块，可按照九宫方式进行适配

**九宫模块划分：**
```
+------+------+------+
|  左上 | 中上 | 右上 |
+------+------+------+
|  左中 | 中心 | 右中 |
+------+------+------+
|  左下 | 中下 | 右下 |
+------+------+------+
```

**适配方式：**
- 页面主要区域拆分9个模块
- 前期交互设定好统一模块规范
- 把控件所处模块区域进行约束

**界面类型分类：**
- **系统UI**：统界面主要以模块信息为主
- **HUD**：主要为固定信息或反馈

### 2.6 弹窗层适配

**适配规则：**
- 弹窗层一般为固定的底板尺寸
- 对应内容位置基于弹窗适配
- 可锁定屏幕位置进行约束处理

**具体实现：**
- 十周年局内通屏类：采用居中适配显示
- 局外弹窗非全屏类：采用固定尺寸，弹窗均固定屏幕中心点显示

# 界面动效规范

> **提取来源：** Figma文档"十周年--交互设计规范" → "--动效规范"页面  
> **更新时间：** 2026-04-14

## 一、系统主界面动效 - 过渡全局通用统一

### 1.1 动效作用与意义

界面过渡动效承载以下重要作用：

| 作用 | 说明 |
|------|------|
| **增加连贯性** | 使界面切换更流畅自然 |
| **强调叙述** | 引导玩家理解内容变化 |
| **清晰关系** | 明确界面层级关系 |
| **减少预判误差** | 降低玩家对跳转的困惑 |
| **引导操作** | 指引玩家注意力方向 |
| **层级展现** | 体现界面空间层级 |
| **吸引用户注意** | 突出重要内容变化 |

### 1.2 时间节点规范

#### 1.2.1 基准时长

| 场景类型 | 时长规范 | 说明 |
|----------|----------|------|
| **通用动效基准** | 300ms | 弹窗弹出时间基准，所有通用无内容表述的动效时间均控制为300ms |
| **剧情对话过渡** | 800ms - 1200ms | 变奏情节、压黑文字交代情节 |
| **游戏进入类** | 800ms - 1200ms | 特殊场景，独立节拍 |

> **注意：** 游戏整体动效时长、速率节奏应一致。动效的播放节奏和顺序决定了玩家在阅读内容上的重点。

#### 1.2.2 响应时间

| 触发类型 | 响应时间要求 | 适用场景 |
|----------|--------------|----------|
| **立即触发** | ≤100ms (0.1秒) | 理想的响应时间 |
| **延时触发** | ≤1秒，不可超过2秒 | 全屏切换、弹出框等 |

#### 1.2.3 动效持续时长

| 元素类型 | 时长范围 | 说明 |
|----------|----------|------|
| **小元素轻微变化** | 200-300ms | 渐隐渐现、大小变化等小范围变化 |
| **较大元素复杂变化** | 400-500ms | 包含大范围缓动位移 |

#### 1.2.4 加载动效规范

| 反馈时间 | 加载样式 | 说明 |
|----------|----------|------|
| 2-9秒 | 循环加载样式 | 如菊花转 |
| 超过10秒 | 进度指示加载 | 显示进度百分比或剩余时间 |

### 1.3 速度和缓冲

#### 1.3.1 缓动曲线类型

| 曲线类型 | 特点 | 适用场景 |
|----------|------|----------|
| **线性 (Linear)** | 属性值变化与时间成正比，均速和骤现 | 与物理属性无关的过渡动画、有规律的加载动画 |
| **Ease Both** | 先加速后减速，起点和终点变化平缓 | 最常用，效果自然，对玩家干扰小 |
| **Spring** | 模拟弹簧震动和阻尼效果 | 复杂物理效果 |

> **重要提示：**
> - 缓动曲线应用范围最广，效果最自然，多用于与物理属性相关的属性变化
> - 在与物理参数有关的变化中（特别是位置变化）尽量避免使用线性变化，否则会带来僵硬不自然的感觉
> - 曲线参数调试工具：http://cubic-bezier.com

#### 1.3.2 速度选择原则

| 动效速度 | 特点 | 适用场景 |
|----------|------|----------|
| **较快** | 易吸引注意力，节省时间 | 需要吸引玩家注意的场景，如位移或速率改变 |
| **较慢** | 较少分散注意力 | 非直接触发类动效，不希望转移玩家注意力 |

### 1.4 过渡效果样式

#### 1.4.1 全屏渐隐（退出效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 画面逐渐暗下去，表达"退出、关闭、消失、结束"的视觉感受，相当于文章的句号 |
| **效果作用** | 分割感受明显，用于没有强连续性、跨层级的界面过渡 |
| **适用系统/界面** | 主界面/系统一级界面的切换，区分系统场景之间的过渡引导 |
| **适用场景** | 页面退出时效果，常与压暗遮黑一起处理（UI层透明度1-0，黑遮罩0-1） |
| **持续时长** | 250ms |
| **触发形式** | 立即触发 |

**示例：**
- 从主界面进入各系统一级界面时，主界面渐隐
- 一级界面退回至主界面时，一级界面渐隐

#### 1.4.2 全屏渐显（进入效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 画面逐渐亮起，具有"轻盈、简约、出现"的视觉感受，属于轻过渡效果 |
| **效果作用** | 渐显时长<200ms时，表达前后关系较为紧密 |
| **适用系统/界面** | 同级界面页签内容区域频繁切换、一级界面打开二级界面 |
| **适用场景** | 进入页面时，建议时长200-250ms |
| **持续时长** | 200-250ms |
| **触发形式** | 立即触发 |

#### 1.4.3 路径/位置移入（进入效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 根据贴边适配的路径进入，表达"出现、引导、流畅"的视觉感受 |
| **效果作用** | 具有视觉引导性，帮助用户感知页面布局、层级结构和重点内容 |
| **适用系统/界面** | 主界面/系统一级/二级界面的切换 |
| **适用场景** | 页面进入时，可选用缓冲类曲线提高舒缓体验感 |
| **持续时长** | 300ms |
| **触发形式** | 延时触发（上界面退出动画播放完后） |
| **样式说明** | 顶层UI根据贴边适配规范移入（-30px → 0），内容层根据页面内容浏览操作习惯移入方向不同 |

#### 1.4.4 路径/位置移出（退出效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 表达"退出、流畅"的视觉感受，但退出路径会使时长感知拉长 |
| **效果作用** | 位移类动效具有视觉引导性，衬托背景场景视觉效果 |
| **适用系统/界面** | 主界面/系统一级/二级界面的切换，建议在有场景包装、空间关系类的界面使用 |
| **适用场景** | 页面移出时，可选用缓冲类曲线提高舒缓体验感 |

#### 1.4.5 放大进入（进入效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 类似镜头前推、视角推进、更深一层进入，具有纵深空间性 |
| **效果作用** | 帮助用户理清前后位置关系，体现系统空间感 |
| **适用系统/界面** | 用于表达很强z轴空间层级关系的页面 |
| **示例** | 世界大地图点击某坐标，进入该坐标详细地图 |

#### 1.4.6 缩小进入（进入效果）

| 属性 | 规范 |
|------|------|
| **效果特性** | 类似镜头后移、视角拉远、后退一步的效果，具有纵深空间性 |
| **效果作用** | 帮助用户理清前后位置关系，体现系统空间感 |
| **适用系统/界面** | 用于表达很强z轴空间层级关系的页面 |
| **示例** | 从某坐标详细地图返回包含该坐标的大世界地图 |

### 1.5 过渡效果搭配注意事项

| 禁止搭配 | 负反馈说明 |
|----------|------------|
| **渐隐 + 渐显** | 会产生中间视觉空白时间太长 |
| **移入 + 移出** | 会产生界面动效用力过渡，频繁切换时路径视觉压力感过重，干扰玩家 |
| **放大 + 缩小** | 在非场景化包装的系统功能性界面中会产生空间混乱 |

## 二、页面跳转导航逻辑处理

### 2.1 返回按钮逻辑设定

#### 2.1.1 基本规则

**游戏内功能入口的按钮逻辑 = 打开并记录位置**

设定从系统进入的第一个功能系统入口为**记录起始点**，也为**重置点**。

#### 2.1.2 跳转路径记录规则

| 跳转逻辑 | 返回逻辑 | 说明 |
|----------|----------|------|
| A → B → C → D | 按原路返回：D → C → B → A | 正常按原路返回 |
| A → B → C → A → B → D | 返回：D → B → A，触发A时直接返回大厅 | 出现第一个系统A时重置路径 |

**核心逻辑：**
- 跳转逻辑中出现从大厅进入的第一个系统【A】为**路径重置起始点**
- 快速导航栏跳转与系统功能入口跳转逻辑共用以上规则

#### 2.1.3 多套娃操作处理

**系统间多套娃操作下的记录：返回路径只记录系统的第一步和最后一步**

**已知问题：**
- 皮肤、武将系统间的颜色过于接近，跳转起来感知不强
- 皮肤系统的详情折叠起来，对查看所有皮肤体验差异的操作不友好

## 五、动效规范总结

### 5.1 核心原则

1. **节奏一致** - 游戏整体动效时长、速率节奏应一致，以300ms为基准
2. **顺序逻辑** - 动效播放节奏和顺序决定玩家阅读重点
3. **避免过度** - 界面动效不应过度用力，避免干扰玩家
4. **空间合理** - 非场景化界面避免使用空间感过强的动效

### 5.2 快速参考表

| 场景 | 推荐效果 | 时长 | 触发形式 |
|------|----------|------|----------|
| 主界面退出 | 全屏渐隐 + 压黑 | 250ms | 立即触发 |
| 一级界面进入 | 路径移入 | 300ms | 延时触发 |
| 二级界面进入 | 渐显 | 200-250ms | 立即触发 |
| 同级tab切换 | 渐显 | 200-250ms | 立即触发 |
| 弹窗弹出 | 放大进入 | 300ms | 立即触发 |
| 弹窗关闭 | 缩小退出 | 300ms | 立即触发 |
